## The one spec amendment

**§1.12 stated its own rule correctly and then contradicted it with its worked
example.** The rule: a tier's rack width — five tiles plus four gaps — must
leave room for the arena's horizontal padding at that tier's lower bound. The
example: *"`378px` inside `400px`"*. But the arena spends `24px` on padding
below `40rem`, so `400px` leaves `376px`, and `378 > 376`.

Two pixels of horizontal overflow, in the `400`–`401px` window.

Nothing caught it before because the rack was `flex-wrap`: five tiles that did
not fit wrapped to a third row. Be precise about what that means — it was not
this same overflow hidden from view, it was a **different** behaviour. The rack
silently degraded to a layout §1.12 does not describe, and no scrollbar ever
appeared. T38 made the grid fixed at five columns, which is the whole point of
the task, and a fixed grid has nowhere to wrap to, so the shortfall surfaces as
overflow.

So: the spec's arithmetic was wrong from the day it was written, and T38 changed
which symptom it produces — a silent relayout became a visible two pixels. That
distinction is the argument for amending the spec rather than the code.

The tile and gap values are the design's own and stand. The boundary was the
wrong number, so the boundary moved: **`408px`**, above the `402px` the
arithmetic bottoms out at so a desktop window narrow enough to show a vertical
scrollbar still clears, and below `412px` so that phone tier keeps the larger
tile.

Amended in `docs/spec/ui-i18n.md` §1.12 and `src/styles/tokens/spacing.css`.
**This is a spec change made mid-milestone on the orchestrator's judgment**, on
the grounds that it is an arithmetic correction rather than a design decision —
the same class of false claim `T27` corrected twice in this handover. Flagged to
Ori as reversible.

## Two corrections to T40, both a token reached for where it does not fit

**The pip radius.** `--radius-sm` is `5px`; the pip is `7px` tall. At that
height the token stops being a radius: CSS scales radii down when two on one
side exceed the side, so `5px` clamps to `3.5px` — exactly half the height — and
the design's softened rectangle renders as a pill. Now a literal `2px`, beside
the width and height already written that way. A dedicated token would be YAGNI:
one fixed shape in one place, and unlike the tile it does not move across tiers.

**The HUD kept the UI sans.** `typography.css` names its own territory —
*"Numerals — equations, tile faces, HUD values. Always the display serif"* —
and HUD values were the last of the three still unconverted. `T35` did tile
faces, `T39` did the equation. Family only; sizes untouched, so `dd.primary`'s
specificity tie against `.entry dd` still resolves to the computed values
`App.test.tsx:139` reads.

## For whoever re-dispatches T42

Do not re-run it as one seven-step sweep; that is what burned ~90 turns and died
in Step 1. The steps are not equally expensive. Steps 1, 2, 3, 5 and 6 are
geometry and computed style — a page resize, `getBoundingClientRect` per cell, a
`getComputedStyle` read, two document properties — and they are also the three
claims the exit gate actually names. Step 4 is the screenshot-diff pipeline that
ate `T37`'s hours, and it is the one step `T41` has already measured from pixels
using the method the journal specifies. Split them: one agent for 1/2/3/5/6,
a second for 4 alone. If budget is tight, **Step 4 is the one to defer** — its
remaining value is independent-read discipline, not a missing number.

Check for orphaned dev servers before starting one. Two were live when this was
written.
