# 2026-09-11 — M5.5g waves 2 and 3: three tasks, and the defect a fixture told the truth about

`T58`, `T59`, `T60`, `T61`. Everything but the measured gate.

## The wave ran serially, deliberately

`T59` and `T60` are marked `parallel_safe`, and they were still run one at a
time. The paths are disjoint; the **worktree** is not. Two implementers running
`npm test` over each other's half-finished edits produce failures neither one
owns, and `T59` had to keep an assertion green in `states.test.tsx` — a file
`T58` was editing. The cost is wall-clock. What it buys is that every red suite
has exactly one author, which is worth more in a phase whose whole product is
evidence.

## `T58` — the fixture that lied, and the one I wrote that lied differently

Three gallery states could not render what they were named for (#105), four the
gate names did not exist, and two more gaps hid defects. All eight are now
surfaces. The state table gained an `interaction` group — the one key that is
not a `GamePhase`, because hover, focus-visible, disabled and reduced motion are
conditions any screen can be in rather than moments the reducer can reach.

**The implementer refused the change the task file suggested, and was right
to.** Step 2 proposed widening `makeFeedbackState`'s default so
`feedback-incorrect` would carry submitted tiles. It checked first: roughly
forty reducer and `GameScreen` tests take that default. It built the state by
running `SUBMIT_INCORRECT` through the real reducer instead — smaller blast
radius, and a state the product actually produces rather than one assembled to
look right.

**Then it built `overflow-marked` on a state the product skips.** A tile marked
for discard, sitting unconfirmed, on the excess-1 overflow — and
`GameScreen.tsx:113-119` dispatches `TOGGLE_DISCARD` and `CONFIRM_DISCARD` from
the same click handler whenever the overflow count is 1. The mark and the
confirm are one press. The reducer permits the state; a player never sees it.

That is the same defect as #105 wearing different clothes, and it is worth
naming as a class: **a fixture can be internally consistent, pass its test, and
still show a moment the product has no way to reach.** The reducer is not the
authority on what is reachable — the component that dispatches is. Rebuilt on
the excess-2 hand, where a first mark genuinely persists, and marked *through*
the reducer, because `TOGGLE_DISCARD` returning the state unchanged is what
would have caught the original mistake.

It also pushed back on my own fix instruction and was right again: at excess 2,
one mark leaves Confirm disabled, so "exactly one tile marked" and "Confirm
enabled" cannot both hold in one state. It kept the mark and asserted the
refusal. The enabled Confirm still has no gallery surface, and does not need
one — it is a primary `ActionButton`, and every other primary button in the
gallery already carries that appearance.

**Hover has nowhere to land.** No component in `src/` declares a `:hover` rule,
and neither does the design system — the only `:hover` in the entire handover
was on anchor elements in the documents' own chrome, and those documents are
now pruned. So the gate's hover coverage will read identical to rest. That is
the system as designed, not a failed probe, and the card says so on its face.

## `T59` — deleting a badge is not deleting a name

The rack's text badges are gone; `isNew` tiles pass `state="reward"`. The
ordering matters and is easy to get backwards: `reward` is the **lowest**
priority of the three, so a reward tile in a read-only rack still reads
`disabled` and one marked for discard still reads `marked`.

Every accessible-name assertion survived untouched, because the badge spans were
`aria-hidden` and never reached the accessible name. Deleting them removed a
visual cue and nothing else. Two visible-text assertions went, each with its
replacement named rather than simply deleted.

**One thing the replacement does not prove.** `getByText("New tile")` became
`toHaveClass(tileStyles.reward)` — the suite's first class-name assertion. It
imports the class from the module rather than hardcoding it, so a rename
propagates, but it would still pass if `.reward`'s rule became empty. jsdom
performs no layout, which is exactly how #84 survived a measurement pass in the
first place. The proof that a reward tile is visibly distinct is a browser
reading, and it moved to `T62` before the task was dispatched.

`.cell` kept `position: relative` after the badge it was written for was
deleted. It is not inert — a positioned cell paints above its unpositioned
siblings, which is what a cell animating out of its own track needs — but the
comment explaining it had gone out with the badge. Restated, so the next reader
does not delete a declaration whose reason has become invisible.

## `T60` — the reordering experiment is the finding

The HUD's specificity tie is gone: `.entry dd.primary` at `(0,2,1)` beats
`.entry dd` at `(0,1,1)` on its own weight, matching `T47`'s fix next door.

What makes this task's evidence good is the **negative control**. Four readings,
not two:

| | natural order | rules reordered |
|---|---|---|
| pre-fix | round `1.5rem`, score `1.25rem` | round `1.25rem` — tie lost |
| post-fix | round `1.5rem`, score `1.25rem` | round `1.5rem` — unchanged |

The second row is the fix. The **first** row is what makes the second row mean
anything: without it, "the readings did not change" is equally consistent with a
harness that cannot detect the flip. `App.test.tsx:139` passed before and after,
in both orders, which is precisely why a passing test was never evidence here.

#95 took the ruling as written — the correct branch's status region states the
submitted value, `Tile` untouched. `product.md`'s `feedback` block turned out
additive rather than binding, and the deciding evidence was in `product.md`
itself: its `gameOver` bullet already says the feedback text is the only place
the real value is stated, unqualified by branch.

I moved that line off `.comparison` onto its own class. `.comparison` is a flex
column with a gap, written for the incorrect branch's stacked pair; the correct
branch states one value and compares it against nothing, so it was wearing a
container class for a container it does not have.

## `T61` — the prune, and a premise that was one third of the truth

The task file held that `decisions.md` is the folder's one live spec dependency.
**Three things are.** `ui-i18n.md:9` makes the whole directory the normative
source for token values, material rules and the motion inventory, and §1.12
names `tokens/motion.css` outright. Pruning to the task file's premise would
have deleted files the spec calls normative.

The rule applied, and recorded in the commit and the folder's own readme:
*keep what the spec calls normative and what a future phase would have to
re-derive; drop what `src/` now implements better and what only the design tool
reads.*

`tokens/`, `guidelines/` and `decisions.md` stay because the spec binds them.
Two canvases stay because nothing in `src/` re-derives them: one presents the
system whole rather than as twenty specimen fragments, the other is the
provenance for every ported motion shape — and this phase's own `10i` strike
note cites `sb-sweep` inside it. Roughly 5,800 lines went.

The reference components earned their own paragraph in the readme rather than a
line in a list. They were superseded, four of their mechanisms were recorded as
defects during the port, and `T60` found another of their `.prompt.md` files
contradicting the component that shipped. **A reference that contradicts the
implementation is worse than no reference** — that is the argument for deleting
a design artifact, and it should be stated rather than assumed.

The eslint ignore went with them, and it went on evidence: no surviving file
matches the lint block's `**/*.{ts,tsx}`, and `eslint . --max-warnings=0` is
green with the ignore removed. A config exception outliving its cause is the
quiet debt this milestone has been clearing.

Two things the prune made false and therefore corrected: `readme.md`'s index
listed four directories that no longer exist, and one comment in
`LanguageToggle.module.css` cited a deleted prompt file. No surviving guideline
covers the language toggle, so the citation went and the sentence it supported
stayed — it is a true statement about the code either way. The task files and
journals of the earlier phases cite the deleted paths throughout, and those are
left exactly as they are.
