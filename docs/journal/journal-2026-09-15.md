# 2026-09-15 — #85 measured in a real window, and M5.5 closes

The last clause of the `M5.5` gate. `T56` and `T62` both swept 320px clean and
both refused to close #85, because both readings came from a fixed-width iframe
and the clause says **in a real top-level viewport**. Ori took the reading. It
took four attempts, and the three that failed are the useful part of this entry.

## The reading that closes it

A real top-level Chrome window, 333 CSS px wide, with a **10px classic scrollbar
taking layout width**, giving 323px of content. Nineteen gallery states, both
locales.

| | en | ko |
|---|---|---|
| `clientWidth` | `323` | `323` |
| gutter | `10` | `10` |
| tier | narrow, `< 408` | narrow, `< 408` |
| peak right edge | `307.3`–`308.8` | `307.3`–`309.0` |
| elements past the right edge | **0** | **0** |
| horizontal scroll | **none** | **none** |
| element count per state | `10`–`85`, none zero | `10`–`85`, none zero |

**§8.5 asks for 320px and this is 323.** The gap is closed by the figure rather
than by extrapolation: the widest right edge anywhere in either locale is
`309.0`. That is below `320` outright, so a `320px` viewport has nothing to
overflow **even if the layout did not respond to the change at all**. The
container is in fact container-bound and would reflow down, but the reading does
not need that to be true.

## Four attempts, and why the first three did not count

**1 — "Gallery looks alright to me."** Narrative. This milestone has spent two
days on the difference between a claim and a reading, most recently a bot's, and
the standard cannot only apply to the bot.

**2 — DevTools device mode at 320px, clean, `gutter 0`.** Two defects. It is
emulation, which is the exact thing the clause refuses, and with no scrollbar
taking layout width it does not exercise the mechanism #85 names. A clean sweep
under an absent condition says nothing. It also could not prove the locale
switched: the control string I picked was a hardcoded English prop in
`states.tsx`, so it read the same in both runs and proved nothing either way.

**3 — A real window via `--window-size=320,900`, `gutter 15`, clean.** A genuine
top-level window with a genuine classic scrollbar — and **Chrome clamped the
width to 500**, giving `clientWidth 485`. That is above the `408` breakpoint, so
it measured the wrong rack tier entirely. My verdict logic checked `gutter > 0
&& clean` and printed **CLOSES #85**, which was wrong, and the data said so on
its face: every one of the nineteen peaks read `469`, because at that width the
arena's max-width binds everything to the same edge. **A sweep where every row
is the same number is measuring the container, not the content.** The instrument
gained a `peaksVary` guard because of it.

**4 — The same real window at 150% browser zoom.** Zoom changes the CSS pixel
size of a real viewport, so media queries evaluate against `333` and the
scrollbar stays real at `10` CSS px. Real window, real gutter, correct tier,
peaks that vary. That is the reading above.

## What the failures have in common

Every one of the first three produced `clean: true`. None of them measured what
the clause asks for. The guards that caught them were not judgement calls — they
were fields printed beside the answer: `gutter`, `tier`, `peaksVary`, and the
per-state element count that `T62` added after a sweep rooted at `main` measured
zero elements on four states and called them clean.

**A verification harness needs to report the conditions of its own reading, not
only its result.** Three different wrong answers here were all indistinguishable
from the right one on the `clean` field alone.

## Two things confirmed on the way

**The locale control finally works.** `langToggle` reports which segment is
pressed and `titleState` samples the Title screen's real localized copy:
`제한된 숫자 타일로 곱셈 문제를 푸세요` renders in Hangul in a real top-level
window, which re-confirms `M5.5b`'s D2 fix outside a test harness. And the two
locales now **differ** — `Overflow — a tile marked` reads `308.8` in en and
`309.0` in ko — so the instrument is locale-sensitive rather than blind.

**The element counts match an independently taken sweep.** Every per-state count
in Ori's reading equals the count `T62` measured in the iframe: `30` for Title,
`46`–`55` across answering, `85` at streak 8, `62`/`69`/`69` across overflow,
`10`/`13`/`10`/`40` across the interaction boards. Two harnesses, two machines,
same numbers. The only difference is *game over — idle* at `23` against `T62`'s
`24`, one element, unexplained and not worth chasing.

## The gate

All five clauses of `M5.5g`'s gate now read met, across `M5.5g` and the two
corrections after it. `M5.5g` itself still shipped meeting three — that is what
it shipped — exactly as `M5.5b` shipped missing the focus gate that `M5.5c`
later closed.

**#85 and #52 close. `M5.5` is done.**
