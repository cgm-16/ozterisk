#85 shipped, production was walked against §8.5 for the first time on a live
build, and the walk that produced those readings is now `e2e/accessibility.spec.ts`
rather than a browser session nobody can repeat.

## §8.5 walked against production

Playwright, real top-level viewport `320 × 400`, Chromium with a classic 15px
scrollbar. `innerWidth 320` / `clientWidth 305` in every reading below, so the
condition #85 needs is present throughout rather than measured away.

| Clause | Reading |
|---|---|
| Semantic buttons | 15 `<button>`; non-button interactive elements **0** |
| Focus order | 14 focusables, **0** positive `tabindex`, **0** inversions |
| Focus indicator ≥ 3:1 | see below |
| Status announced | `role="status" aria-live="polite"`, carrying the verdict |
| Not colour alone | the verdict is a word in that same region |
| Target ≥ 44px | min across all buttons **49.8 × 44** |
| No h-scroll at 320 | `scrollWidth 305 = clientWidth 305`, `scrollLeft 0`, **0** elements past the edge |
| Korean does not clip | 42 elements with the disclosure open, **0** overflowing their box |
| Reduced motion | 4 elements animate normally → **0**; `--press-offset` `2px` → `0px` |

**The focus indicator is the interesting one.** It is two-tone —
`inset 0 0 0 2px #e8cd85, inset 0 0 0 3px #16352b` — and each tone carries a
different surface:

| Surface | Gold tone | Dark tone |
|---|---|---|
| Ceramic face `#fdf8ec`→`#e6d7ba` | 1.47 / 1.10 | **12.55 / 9.37** |
| Felt `rgb(7,23,17)` | **11.85** | 1.38 |
| Gold active toggle segment `rgb(201,165,74)` | 1.51 | **5.68** |

Every surface has one tone clearing 3:1. A single-tone gold ring — what the
handover shipped, D1 — reads `1.10` on ceramic and `1.51` on the gold segment.
Both failures, on the two most-focused controls in the app.

### What the walk did not cover

Stated rather than implied, because a checklist that records only its passes is
not a record:

- **Three phases of five.** Title, answering, feedback. Overflow needs an
  eleven-tile rack and game over needs a losing run; neither is reachable without
  playing many rounds, so the button, focus-order and target-size clauses are
  unverified on those two screens.
- **Touch input.** Synthetic taps would have told us nothing a click did not.
- **Screen readers.** The live region exists and carries the right text; no AT
  was asked to announce it.

## The walk is now a spec

`e2e/accessibility.spec.ts`, seven tests, 2.6s. It owns eight of §8.5's nine
clauses; `viewport.spec.ts` keeps "no horizontal scroll at 320px", which it
already sweeps across nineteen gallery states and the arena.

Two traps, both found by the tests failing rather than by reading the code.

**Submit stays disabled until every slot is filled.** The slot count is the
product's decimal length and the product is random, so a helper that spends one
tile deadlocks on a two-digit product — Playwright retried the click for 57
cycles before timing out. The slot count has to be read off the screen.

**The focus ring transitions in, and a computed style read on the focus frame
returns the transition's *start*.** That start is a fully transparent ring, which
parses as `rgb(0,0,0)` and measures `1.14` against the felt — so the first
version of the contrast test failed against a ring that was in fact correct. The
fix is to wait the transition out:

```ts
tile.focus();
await Promise.all(tile.getAnimations().map((a) => a.finished.catch(() => {})));
```

This is the same family as the frozen-`document.timeline` trap from `T56`
(`journal-2026-09-12.md`): **a property mid-transition does not report the value
you are trying to measure, and it fails in the direction that looks like a real
defect.** The earlier case froze the clock and made motion unmeasurable; this one
samples too early and makes a passing indicator look broken. Both are cured by
reading at a point the browser agrees is settled, never on the frame the change
lands.

### Instrument check

Each test carries the count it swept, so a sweep rooted at the wrong node cannot
report clean. Beyond that the contrast gate was checked against the case it must
fail: collapsing `--ring-focus` to a single gold tone produces

```
Error: best tone against ceramic stop 1
Expected: >= 3
Received:    1.47
```

which is D1's own figure. The reduced-motion test carries its check inline — it
asserts motion **exists** before emulating the query, so it cannot pass by
measuring a page that has no motion to remove.

## Guardrails, for the record

`prod` is now held by a repository ruleset rather than by convention, and agent
sessions authenticate with a fine-grained token that has no **Administration**
permission — `branches/prod/protection` returns `403 Resource not accessible by
personal access token`. Ruleset writes need that same permission, so the branch
model is no longer something an agent can edit out of the way, including by
accident.
