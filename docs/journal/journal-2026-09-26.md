# 2026-09-26 — Fixtures that §2.5 allows but play cannot reach

Found while handling review feedback on #165, and deliberately not fixed there.

Not fixed, noted:

- `makeFeedbackState` sets `lastResult.kind: "incorrect"`, and
  `makeOverflowState` builds on it. So does the copy of both fixtures in
  `docs/spec/architecture.md`. Every overflow state in the tests is therefore
  one that play cannot reach: an incorrect submission cannot overflow
  (product.md §1.7a), so only a correct answer leads to `overflow`. The same
  goes for a feedback state after a discard.
- §2.5 does not list the pairing of `overflow` with a correct `lastResult`
  among its invariants. The fixtures are legal under §2.5 as written; they are
  only unreachable.
- One test depends on the value: the overflow test at
  `GameScreen.test.tsx:427` asserts that the preserved feedback reads
  "Incorrect". That is the unreachable state itself, so a fix changes that
  assertion along with the fixture. A fix would give the overflow fixture a
  `correct` result, and ask whether §2.5 should state the pairing, since it
  can be derived.

# 2026-09-26 — M7 face tiles: calls made in the build, and risks to watch

Calls made while building T76–T81, beyond the handoff:

- **`generateRewardTiles` takes the mode, not a rate.** The plan passed
  `faceRate` from App. That is the pattern architecture.md § Tuning surface
  forbids ("a dial passed as an argument is a dial that can be silently
  overridden"). Ori chose the mode. Endless takes no face-gate sample at all,
  so its reward sequence is unchanged. Classic takes two samples per digit
  reward, so any test that scripts Classic randomness must feed the gate.
  `classicRewardSamples` in `App.test.tsx` does this.
- **The T77 commit narrows the consumer sites only far enough to compile**
  (Ori). Making `Tile` a union broke every `tile.digit` read in T78's and
  T79's paths. Those lines were stopgaps until T79 passed tiles through.
- **Face glyphs scale with the tier's digit size**, at the ratio of the
  handoff's px values (36/34, 25/34, 18/19, 11/19). The handoff gives fixed
  px, and the stepped rack shrinks `--size-tile` to 25px on 44 × 55 tiles,
  where a fixed 36px letter would crowd the inlay. At the design size the
  rendered values are exactly the handoff's.
- **T76's picker grep** also matches the gallery's entry "picker" in
  architecture.md §2.7. That is a different meaning of the word. The gate
  was left as written, and the hit was reported rather than reworded.

Risks to watch in real play:

- **A Garamond `O` sits close to `0`.** The inlay is the only visual
  separator, and the spoken label carries the full set. If players misread
  Odd as a zero, the answer is the letter's treatment, not a new material.
- **`FACE_RATE` 0.08 was not simulated.** The measured bracket at skill 95%
  is 56% (0.05) to 65% (0.10). Real players misplace faces, which the
  simulator does not, so expect the win rate below the bracket's midpoint.

Not fixed, noted:

- On a correct answer, `RoundResult.submittedValue` always equals
  `correctValue`, so FeedbackPanel prints `correctValue` for it. The field
  now carries information only on an incorrect answer. Narrowing the type
  per `kind` would say so, but it touches every result fixture.
