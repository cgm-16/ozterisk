# 2026-10-19 — How mode prototypes run

## The rule

Ori ruled on how the research pool's modes (`docs/research/game-modes/`) are
tried:

- A prototype lives on its own branch, with a draft PR against `main` so
  Vercel builds a preview to playtest on.
- **Nothing merges** until the playtest passes and `docs/spec/**` has been
  amended. A merged mode is a spec change, and the spec is canonical.
- A failed playtest closes the PR unmerged, and the result goes in the journal.

A prototype branch may never land, so its journal entries do not ride on it.
This rule and every playtest result reach `main` in their own docs PR. A closed
prototype PR keeps its branch, design doc and code on GitHub; the journal entry
links it.

## A fixed playtest set on Puzzle's preview

Live deals would almost never show a sacrifice (0.7% of accepted tables, by the
draft's §5), and an observer could not tell a Medium table from a Hard one, so
§7's "Medium and Hard feel the same" rule could not be applied. Ori therefore
allowed one exception, on the preview only: every tester's first three Puzzle
deals are the same three tables, Medium, Hard and the sample, and live deals
follow. A reload replays the set. That is a replayable run on a public URL,
which the AGENTS.md seed line and `product.md` §1.17 forbid, so the set is
removed before the branch can merge. The precedent is #177, whose `?rack=`
switch ran on a branch that closed unmerged.
